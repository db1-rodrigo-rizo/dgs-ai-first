# Exercício 2.1 — Tarefa 1: Mapeamento Necessidade → Server MCP

> Mapeamento das necessidades do projeto NovaTech Assistant para os *reference servers* MCP locais e gratuitos (`filesystem`, `git`, `memory`, `everything`), conforme Anexo C.

| Necessidade | Server | Tools/Resources expostos | Quem consome | Acesso | Pasta(s) | Motivo |
|---|---|---|---|---|---|---|
| Ler/editar código, specs, skills | `filesystem` | Tools: `read_file`, `write_file`, `edit_file`, `list_directory`, `search_files`, `create_directory` | Copilot e Claude, durante implementação (Exercício 2.2) e geração de skills (Exercício 2.3) | Leitura e escrita | `./src`, `./specs`, `./skills` | Como Copilot e Claude atuam como assistentes de codificação, precisam ler e escrever no código-fonte, além de gerar e ajustar tasks em `./specs` e skills em `./skills`. |
| Ler documentação de negócio | `filesystem` | Tools: `read_file`, `list_directory`, `search_files` (sem `write_file` habilitado para este escopo) | Claude e Copilot, durante consulta a regras de negócio para gerar código ou responder dúvidas | Somente leitura | `./docs/novatech` | A documentação de negócio é a fonte da verdade (premissas de POL-001, PROC-042, SLA-2024). O agente consulta para gerar código correto, mas nunca deve alterar esse conteúdo. |
| "Recuperar" chunks | `filesystem` | Tools: `read_file`, `search_files` | Claude, ao simular respostas do assistente ou validar cenários de teste do Anexo B | Somente leitura | `./data/retrieval-corpus` | Em produção, a recuperação seria via Azure AI Search. Nesta fase local, a necessidade é simulada por um arquivo estático (`chunks-novatech.md`), servido como somente leitura, para validar o pipeline antes da integração real. |
| Histórico, diffs e branches do repo | `git` | Tools: `git_status`, `git_log`, `git_diff`, `git_show` (leitura); `git_add`, `git_commit`, `git_create_branch` (escrita) | Claude e Copilot, para contexto de mudanças; commits/branches sujeitos a autorização do dev | Leitura e escrita (commit/push dependem de decisão do dev) | repositório local (`.`) | O server tecnicamente permite leitura e escrita. A exigência de que o agente sempre pergunte antes de commitar é regra de processo do AGENTS.md (coerente com o gate "code review + 1 approval"), não limitação técnica do server. |
| Glossário e decisões persistentes | `memory` | Tools: `create_entities`, `create_relations`, `add_observations`, `search_nodes`, `read_graph` | Todo o time (via Claude), para registrar e consultar linguagem ubíqua e decisões do projeto | Leitura e escrita | grafo local (interno ao server) | Precisa persistir entre sessões — linguagem ubíqua e decisões não podem se perder a cada conversa nova. |
| Explorar primitivas de MCP | `everything` | Tools de demonstração (echo, add, sampling, etc.); não mapeia nenhuma necessidade real do projeto | — | Não configurado neste projeto | — | Excluído por decisão deliberada de least privilege: não atende a nenhuma necessidade funcional listada no exercício. Menos servers ativos = menor superfície de risco, sem perda de capacidade real. |

---

**Nota:** os nomes exatos das tools de cada server (especialmente `filesystem` e `memory`) devem ser confirmados no README oficial de [`modelcontextprotocol/servers`](https://github.com/modelcontextprotocol/servers) antes da configuração final, já que podem evoluir entre versões.
